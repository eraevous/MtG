# kb.counters: counter identity, 2026-10-31

Zach asked for counter identity as a KB release (C-015, C-016): +1/+1 vs -1/-1, named vs generic wording, nest counters (Twitching Doll), poison on players, and the order of operations on entry (Reaping Willow with Loading Zone).

Trade-offs:
- **A second reader, on purpose and for now.** The grammar layer already records `counter_kind`, but the KB build does not consume the grammar DB, and its counter parse has known errors (Puca's Covenant's kind read as "of"; proliferate compiles to no counter operation). `kb/counters.py` reads exact contract text and Oracle text in the KB build so this release does not wait on the grammar layer. That makes two readers of the same text, which is the drift AGENTS.md warns about. C-017 records it; the fix is to converge on one reader, not to grow both.
- **Card-level facets go in `derived_facts`, not a new table.** No schema change; `fact_kind = 'counter_facets'`, `derivation_version = card-counters-0.1.0`.
- **Keyword macros come from a list** drafted from the CR definitions, because reminder text is stripped (as in kb patch 4). A missing keyword yields no facet, not a wrong one.
- **Sign is never assumed.** Facets keep the kind; the DIO's state table says a counter may be a buff, a gate, a clock, a capacity or a liability.
- **The order-of-operations rule is a note with CR citations, not a simulation.** It applies to cards that enter with -1/-1 counters. A scenario-backed runtime check belongs to the scenario registry once someone reviews it.
