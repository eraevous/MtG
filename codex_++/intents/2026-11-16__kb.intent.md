# 2026-11-16 kb: C-001 root cause and C-006 CI job

Author: claude:mtg#wake-20261116-21 · Reviewer: none yet · model=claude-opus-5-5 · handoff HO-MTG-20261116-QVBX

- **Finding.** The T7 byte-identical rebuild passes under SQLite 3.53.1 (the library that wrote release r20261104, per the database header) and fails under SQLite 3.45.1 (Python 3.12 in this container; the CI runner's SQLite is not checked yet, and the kb job is safe either way). The SQL dumps of the two rebuilds are identical. So C-001 was environment, not nondeterminism.
- **Trade-off 1: new test outside kb/.** kb/MANIFEST.sha256 pins kb/test_acceptance.py, so editing T7 breaks T7's own manifest test until a new KB release. The content check lives in tests/test_kb_rebuild_content.py instead; folding it into T7 is for the next release.
- **Trade-off 2: CI skips T7's byte rebuild with its existing switch (KB_SKIP_REBUILD=1).** Nothing is lost: the new file checks content on every run and bytes whenever the SQLite matches the release. This is a skip of a test that cannot pass on that runner by construction, not a skip to hide a defect; it is called out in the PR for Zach.
- **Cost.** The kb job downloads a 30 MB public asset and spends about a minute on the suites; no secrets, no new dependencies.
