# Agent grounding in the KB and DIO (2026-10-30)

Zach ran a blind Codex thread against the repo. It evaluated new cards from the purpose docs, the inventory and `mtg_eval`, never opened the DIO, and found no KB database. Its interaction analysis was its own reading of Oracle text.

Causes found:
- No entry point (AGENTS.md, README) routed card questions to the DIO or the KB-backed `mtgtools` verbs. AGENTS.md named the DIO only as an authority.
- The databases are gitignored, and no command could fetch them.
- `mtg_eval` reads no DIO contracts, even with the KB present (C-012). README showed it first.

Trade-offs:
- **Guide plus labels, not enforcement.** Nothing can stop an agent from skipping the guide. So the fix makes the path short (AGENTS.md section, one status command) and makes skipping it visible: `grounding` in every `mtgtools` envelope, and a required grounding line in answers.
- **mtg_eval is left untouched.** Adding a grounding line to its output would change files pinned by kb/MANIFEST.sha256 and break T7 until the next release (as in C-011). It is logged as C-012 for the next release instead.
- **`dio` is retrieval, not a new semantic layer.** It quotes sections and returns no claims, so it cannot become a competing interpretation (P-01).
- **Release metadata synced to r20261030.** The repo's code was already r20261030 (PR #12), but its release notes, SOURCE_MANIFEST.json, MANIFEST.sha256 and release.py still said r20261028. They were copied unchanged from the released zip. With them, all 61 KB tests pass against the r20261030 databases.
