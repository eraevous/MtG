# 2026-11-01 mtgtools find: functional retrieval

**Trigger.** The first practical-question run showed that the most common question ("free cards that do X in these colors") had no verb. Kate (2026-11-01) said to build it next as narrow retrieval, without waiting for the role audit or C-023, and supplied eight acceptance cases.

**Trade-off.** `find` reads `capability_claims` through a declared role vocabulary. It does not parse Oracle text: Kate asked for no new regex engine, and P-01 forbids one. The cost is that its recall is the detectors' recall, so every answer says it is nonexhaustive. The shape (repeatable, one-shot, conditional) comes from the KB contract that holds the matched phrase. "Conditional" means the contract records an unbound condition, which over-flags some cards (575 contracts carry an unbound "if"), so it is phrased as "read before counting". The broad inventory tag "Sacrifice synergy" was left out of the sacrifice family's supports: it tags fetchlands and Food, so it buried the real payoffs.

**Data vs tool.** The tool only exposes what the KB records. Better results need data work: reviewed capability claims, C-012 (roles from DIO contracts), and the inventory Roles tags (C-013).
