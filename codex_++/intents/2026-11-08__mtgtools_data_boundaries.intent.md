# Aegis: reference data cannot grant operational authority

The user requested defenses against MtG becoming a lane for malicious natural
language instructions. Source text already reaches conversational consumers in
JSON, but the envelope did not explicitly separate domain evidence from tool
permission. Add one code-owned versioned descriptor at the existing boundary,
not a new filtering subsystem. Preserve card/user text and evidence grades.

Trade-off: additive JSON metadata still requires consumers with closed schemas
to upgrade. Bump the tool patch version to 0.4.3 and document the v1 boundary
schema. This does not establish model resistance or authenticate source labels.
No DIO source, purpose contract, review state or inventory ownership changes.
Tests use synthetic role spoofing, claimed authorization, nested metadata and
normal imperative Oracle text; the expected behavior is lossless data, not
keyword rejection. Publication and integration are held for parent review.
