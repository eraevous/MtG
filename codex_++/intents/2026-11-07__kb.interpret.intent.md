# 2026-11-07 kb: interpretation log and its writer (DEC-152, HO-MTG-20261107-92QA)

**Trigger.** Zach on the KB work: "it's not working right. It's not good." DEC-152 asks for a dialogue with Kate over cards and mechanics the KB marks blocked or unresolved, recorded round by round in an append-only, hash-chained file written only by a `review.py`-style command.

**Trade-offs.**
- The writer is `kb/interpret.py`, not a `python3 -m mtgtools interpret` verb. `mtgtools.cli` is read-only by its purpose contract ("never writes the Sheet, the KB or the overrides"); the two existing override writers (`review.py`, `reconcile.py`) already live in `kb/`, which is a declared semantic owner. Putting the writer where the other writers are keeps one module responsibility per module and avoids a Drift review for tonight's work. A read-only `mtgtools interpret show` can come later without that cost.
- The log binds a card row to the KB's current `oracle_text_sha256` but **not** to a contract SHA. The question in a round is usually "what does this text mean", which outlives the drafter's version of the contract; a `--contract` id is optional context, checked only for existence and ownership. Staleness is therefore about text, not drafts.
- Hard-coded `verification_state: candidate`. The CLI has no flag for it. Zach asked that nothing be promoted; the cheapest way to make that true is to leave no door.
- A reading needs a citation. `oracle` is allowed as a citation, because many questions are decided by the text alone and demanding a CR number would invite decorative citations. It is still a stated basis a reviewer can check.
- `agreed` needs two parties, not two models. Two models under one actor are one voice.
- No DB table and no replay. The file is the single home (DIO §2). The build does not change, so no release is needed to start the dialogue.
- The empty log starts with one `#` header line. `chain.read` skips comment lines; `drift_check` treats the first commit as the base, so appends after it are checked as append-only.

## Addendum, same day (claude:mtg#wake-2026-11-07-21): Kate's four amendments as optional fields

**Trigger.** `kairos/kate-round-17.md` landed (Kate AGREEs with the protocol, four amendments; coordinator addendum to HO-MTG-20261107-92QA: fold them in as optional fields so Zach can adopt or drop them without a schema change).

**Trade-offs.**
- Optional, not required. Requiring `layer` or `scenarios` on every row would adopt the amendments on Kate's and my say-so; only Zach decides protocol. Optional + vocabulary-checked gives him both doors.
- The three new top-level fields join `FIELDS`, so they are hashed (absent → `None`). Safe because the log holds no rows yet; after the first real row this would have been a chain-breaking schema change and would have needed a `supersedes` convention instead.
- `disagreement_type` is refused on an `agreed` row. Kate's amendment 3 is about not resolving disagreement by consensus; a type on an agreement would be decoration.
- `scenarios` comes as a pair. A positive case alone is the confirmation-only pattern the blind tests already show; the near-miss is the part that catches a wrong reading. `kb_output_changed: null` is allowed because the scenarios can be written before the KB is run against them, and most will be at first.
- Per-reading `independent` is a self-report. The writer cannot verify that a party did not see the other's reading; the relay order (coordinator asks both before showing either) is what makes it true, and that is a protocol step, not a check.
