# Intent: mtgtools 0.2.0, the Terra patch set (2026-10-27)

@ai-cadence: drift
- **Why.** Two runs of Kate's eight Terra questions, run 1 by the builder and run 2 by a fresh-context agent, both on mtgtools 0.1.0 @ 4951faa. Kate's assessment of them set the smallest justified patch set: fix `check` (P0), qualifier-aware and self-interaction matching (P1), more selective discovery output (P2), plus the collection policy as an operational setting. The frozen runs are not re-scored with it.
- **What changed.**
  - `check` reports `evidence_grade` (the source) apart from `verdict` (whether a structured `assert` holds). `grade` is decision_grade only when a decision-grade source settles the assertion. Free text is never judged.
  - Every link carries a qualifier status and a basis:
    - **compatible**: a recorded qualifier is satisfied.
    - **unresolved**: the contracts don't record what would decide it (counter type, token characteristics, face, controller).
    - **incompatible**: rejected and reported in `rejected_links`.
  - Same-card links and links into self-enter triggers are admitted in two cases: a copy or return of a target whose type fits, or a card that returns itself.
  - Grammar-layer loops that no KB contract supports are listed as `loops_contested`, apart from the others.
  - `hypothesis` adds `acts_on`: targeted abilities whose target type fits the other card, such as Decoction Module's bounce on Terra. Rejecting one route never hides the card.
  - A theme seed keeps only links in which the themed ability itself takes part, and lists links on the theme's own pathways first. An unknown seed names the supported themes.
  - `decks/collection_policy.json` records Zach's decision that Steph uses his collection, with TMNT, Ashling, Rootha and Dina protected. `context` reports it, and `card` reports the availability tiers.
- **Dissent review** (AGENTS.md: downstream deriving what upstream should own).
  1. *Which purpose might this violate?* P-01. The 0.1.0 intent said qualifier-aware matching "belongs to the KB, not here", and this release does part of it here.
  2. *Evidence for the concern.* `_target_types` and `_self_obs` read words from the contracts' eligibility and event phrases. Those phrases are text, not structured qualifiers. Logged as C-010.
  3. *Counter-evidence.*
     - Only the contracts' own recorded fields are read, never `oracle_text`, apart from the `check` assertion `text_contains`, which is a lookup.
     - The words read are limited to type-line vocabulary and a leading "this".
     - Anything undecidable stays unresolved. Nothing here creates a new interaction meaning; it only refuses matches the record contradicts.
  4. *If the concern is right.* The KB and mtgtools could disagree about a card's targets or self-trigger, and the disagreement would go unnoticed. One example already exists: Bandit's Talent op002 has `hook_subject: others`, but its event phrase is "this Class enters".
  5. *What to decide.* Zach decides whether the KB should record target filters and self-subjects as structured qualifiers (the proper home). If so, mtgtools drops its phrase reading.
- **Trade-offs.**
  - Counter type is never inferred, so energy-to-lore links stay unresolved, not rejected. They are only removed from the loop list, through the KB-consistency check.
  - Volume falls only modestly: Terra focused gives 742 kept links and 666 rejected. Ordering does most of the work, by grouping each pathway with its qualifier basis and putting rare groups first.
- **Not done (deferred by Kate).** An Oracle lookup for unowned cards, and `compare` on hypothetical lists.
